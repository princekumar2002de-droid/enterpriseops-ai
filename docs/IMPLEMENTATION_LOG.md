## 2026-11-02 — Task 3: deterministic matching engine, KPIs and API v1

**Goal:** implement the business rules as tested code, persist versioned runs, expose results and KPIs
through the API, and measure accuracy against the ground truth (decisions D1–D3 approved).

### Built
- **Migration 0003** (autogenerated + reviewed): `ops.match_run`, `invoice_result`, `line_result`,
  `exception`, `duplicate_candidate`; schema `agent` with 9 curated views; `eops_agent_ro` narrowed to
  the views (ADR-022); column grant `UPDATE (payment_block)` for `eops_app` (D1 / ADR-024).
- **Matching engine** (`app/services/matching/`): `snapshot.py` (typed, immutable input from DB or
  generated rows), `rules.py` (T1–T5, R2, R5 as pure functions), `duplicates.py` (transparent scoring,
  ADR-025), `engine.py` (receipt-order processing, precedence R1–R6, severities, amount at risk),
  `repository.py` (one transaction, advisory lock, versioned run, payment blocks), CLI
  `python -m app.services.matching`.
- **Evaluation harness** (`backend/evaluation/`): per-code precision/recall, hard-negative
  false-positive rate, threshold sweep, Markdown report, CLI (`matching`, `tune-duplicates`, `db`).
  Report: `backend/evaluation/reports/matching_seed42_full.md`.
- **KPI service** (`app/services/kpis.py`): 12 KPIs in SQL over the agent views, 5 with supplier
  breakdown (ADR-026).
- **API v1**: `POST /matching/runs`, `GET /matching/runs/latest`, `GET /invoices`,
  `GET /invoices/{id}` (three-way evidence), `GET /exceptions`, `GET /kpis`, `GET /kpis/{id}`;
  uniform error envelope with request ID; paging; strict parameter validation.
- Tests: 68 new (105 total).

### Verified (dev workspace)
- Migration 0003 up/down/up; `alembic check` → no drift.
- **Seed 42 (reporting seed): precision 1.000 / recall 1.000 for all 10 codes, 0 of 1,051 look-alike
  invoices flagged** — all D3 targets pass; same on 4 more full and 5 small seeds.
- Duplicate threshold tuned on seed 7 only (D2): perfect plateau 0.50–1.00, chose 0.60.
- DB run identical to in-memory run (948 exceptions / 3,551 documents, 1.4 s end to end); 542 invoices
  blocked, payment block set on the 87 unpaid ones.
- API smoke test on the full dataset; 2 KPIs cross-checked against an independent Python calculation.
- 105 tests, 98 % coverage (matching core 100 %), ruff/format/mypy strict clean.

### Problems found and fixed during the task
1. **Late payment rate 35.9 % (data-realism bug found through the KPI layer).** Root cause: the
   generator scheduled on-time payments at "due date −4…+3 days", so ~3 in 8 were paid 1–3 days late.
   Fix: payment runs pay at due date −5…0 days; ~8 % are paid late on purpose. Generator → **1.1.0**,
   new seed-42 fingerprint `32a2a5b2249fe8dd…`; labels unchanged (2,002); late payment rate now 12.84 %.
   Rejected alternative: a grace period in the KPI — it would have hidden a data defect.
2. **Doc sync gap:** a comparison before starting showed that four docs on the developer Mac were older
   than the workspace copies (the "close Task 2" update had not landed). Re-synced with this delivery;
   delivery is now verified by checksum.
3. Lint `S608` (possible SQL injection) in the KPI module reviewed: SQL is assembled from module
   constants only, all user input is bound → false positive, suppressed for that file with the reason
   in `pyproject.toml`.

### Decisions
ADR-022 (agent views), ADR-023 (pure engine, versioned runs), ADR-024 (payment block grant),
ADR-025 (duplicate scoring + tuning), ADR-026 (KPI catalog); rules T4, T5, R6 added to
PROJECT_REQUIREMENTS §8.2.

### Backlog created
- Harder duplicate variants in the generator (re-issued number, amended amount) so the threshold
  trade-off becomes measurable.
- CI housekeeping still open: pin `ubuntu-24.04`, evaluate `gitleaks-action` v3.

## 2026-11-02 — Task 2: ERP data model and synthetic dataset

**Goal:** SAP-aligned tables, a reproducible synthetic dataset with labeled exceptions (ground truth),
least-privilege database roles, and a validation report.

### Built
- `app/db/tables.py` — 21 tables (erp 15, iam 2, ops 1, eval 3) in SQLAlchemy Core with CHECK
  constraints, composite FKs (incl. GR reversal → original receipt), fixed naming convention.
- Migration `0002` — autogenerated from `tables.py` and reviewed; MANUAL additions: `eval` schema,
  8 business roles (`iam.role`), DB group roles `eops_agent_ro` / `eops_app` / `eops_action` with grants.
- `migrations/env.py` — compares only our schemas (`include_name`), type comparison on.
- `data_generation/` — `reference.py` (company, plants, terms, tax, tolerances, material catalog,
  personas), `generator.py` (clean P2P history), `scenarios.py` (10 exception + 7 hard-negative
  scenarios, labels), `loader.py` (one transaction, TRUNCATE…CASCADE, refuses production),
  `validation.py` (19 SQL checks + summary), `__main__.py` (CLI).
- Health probes (`/health/*`) now logged at DEBUG (was flooding logs every 15 s).
- Tests: 27 new (37 total). Coverage now also measures `data_generation`.
- New dev dependency: **Faker** (realistic names/cities/IBANs). NumPy/Pandas deliberately not added (ADR-019).

### Verified (dev workspace, PostgreSQL 16)
- `alembic upgrade head` / `downgrade 0001` / `upgrade head`; `compare_metadata` → no differences.
- Full profile, seed 42: generated + loaded in 2.1 s, 35,559 rows (7,604 GR lines, 3,208 payments,
  2,002 labels), **19/19 validation checks pass**, 18.9 % of invoices with exceptions,
  content hash `477673a2b9fa2927…`.
- Tolerance semantics checked numerically: PRICE_VARIANCE ≥ 4.00 % and ≥ 17.36; within-tolerance
  look-alikes ≤ 1.50 % and ≤ 49.45; small-difference look-alikes > 2 % but ≤ 4.45.
- 37 tests pass, coverage 99 %, ruff/format/mypy strict clean.

### Problems found and fixed during the task
1. **Generator hung on the full profile.** Root cause: the material catalog allowed only 295 unique
   descriptions but 400 were requested, so the "draw until unique" loop never ended. Fix: catalog
   expanded to 501 combinations, sampling rewritten to shuffle all combinations (no retry loop), and a
   capacity guard raises `ValueError` instead of hanging (tested).
2. **Small profile, seed 2 lacked `HN_SMALL_DIFFERENCE`.** Root cause: too few invoice lines worth
   20–100. Fix: range widened to 20–150 with the markup capped at 4.50 / line value, so the
   difference stays under the 5.00 limit. Verified on small seeds 1–12 and 6 full-profile seeds.

### Decisions
ADR-017 (tables in code + drift test), ADR-018 (`eval` isolation), ADR-019 (generator dependencies and
location), ADR-020 (DB roles), ADR-021 (labeling semantics); business rules T1–T3 / R1–R5 added to
PROJECT_REQUIREMENTS §8.2.

### Verified on the developer Mac
- `docker compose up -d --build`: migrate ran `0001 -> 0002`.
- Generator (uv 0.13.6, CPython 3.12.16): 1.1 s, **same content hash `477673a2b9fa2927…`** as the
  Linux workspace → reproducible across platforms; 19/19 validation checks.
- `ruff`, `mypy` (26 files) clean; `pytest --cov` → **37 passed, coverage 99 %**.

## 2026-11-02 (afternoon) — Task 1: verification on the developer Mac + test-config fix

### Verified on the developer machine (MacBook Air, Apple Silicon)
- `docker compose up --build`: images built (`python:3.12-slim`, `pgvector/pgvector:pg17` → PostgreSQL 17.11); `eops_test` created by the init script; `migrate` ran revision `0001` and exited 0; the API started; `GET /health/ready` → **200**; the container healthcheck (`/health/live` every 15 s) is passing.

### Bug found and fixed
- **Symptom (found by review, before it caused a false result):** `pytest` read `EOPS_TEST_DATABASE_URL` only from the shell environment, not from `.env`. On the Mac the 4 integration tests would have been skipped, although the README says `.env` enables them.
- **Root cause:** `pydantic-settings` loads `.env` only for the `Settings` model; the test fixtures read `os.environ` directly.
- **Fix:** `tests/conftest.py` now calls `load_dotenv(<repo>/.env, override=False)` before anything else. Shell/CI variables still win, and `EOPS_ENVIRONMENT=test` is set first so tests don't inherit `local`. `python-dotenv` was added as an explicit **dev** dependency (it was already installed transitively via pydantic-settings; relying on a transitive dependency is fragile).
- **Verification:** with `.env` → 10 passed; without `.env` → 6 passed / 4 skipped; CI mode (shell env + `EOPS_REQUIRE_DB=1`) → 10 passed.

- Local quality gate on the Mac (uv 0.13.6, CPython 3.12.16, against the compose database): `ruff check` clean, `mypy --strict` clean, `pytest --cov` → **10 passed, coverage 95 %**.

- Repository published: https://github.com/princekumar2002de-droid/enterpriseops-ai (commit `4041df2`, 38 files; `.env`/`.venv` confirmed absent).
- **First GitHub Actions run #41474098669: success.** Docker image builds ✓ (14 s), Secret scan ✓ (11 s), Backend lint/types/tests ✓ (35 s) — integration tests ran against the `pgvector/pgvector:pg17` service container.

### Task 1 gate: PASSED ✅
